# Оценка качества генерации SQL

## Цель

Мы проверяем, может ли система **сгенерировать исполняемый SQL**, который возвращает **тот же результат**, что и известный эталонный запрос. В отличие от оценки поиска, здесь тестируется полный путь генерации: контекст из векторного хранилища (схема базы и похожие примеры) и синтез запроса языковой моделью.

Качество измеряется **выполнением** эталонного и сгенерированного SQL в SQLite с последующим сравнением полученных таблиц.

## Что мы тестируем

Качество генерации оценивается для комбинаций:

- **Модель LLM** — можно сравнивать несколько моделей в одном прогоне;
- **Стиль комментариев к DDL** — краткий inline или структурированный yaml;
- **Стиль описания запроса** — краткий, бизнес- или технический.

Для каждой комбинации все артефакты согласованы между собой:

- используется одна и та же модель LLM (остальные настройки генерации не меняются);
- схема базы представлена в выбранном стиле комментариев;
- к базе подключается соответствующий вариант SQLite с тем же стилем описания;
- текст запроса берётся из описания в нужном стиле либо из отдельного источника (например, исходная формулировка запроса без переписывания).

Число комбинаций за один прогон равно произведению числа моделей, стилей DDL и стилей описания.

## Входные данные

Для оценки нужны:

| Данные | Назначение |
|--------|------------|
| Таблица с описаниями запросов | Текст запроса и уровень сложности для каждого примера |
| Эталонные SQL-скрипты | Референсный код, используемый при обучении фолдов |
| Эталонные результаты выполнения | Таблицы, полученные при выполнении эталонного SQL |

Перед оценкой:

1. Оставляются только примеры, для которых уже есть эталонный SQL.
2. Удаляются дубликаты пар «идентификатор — описание — SQL».
3. Для каждого примера формируется одна строка оценки: идентификатор, текст запроса, сложность.

## Пайплайн оценки

Для каждой комбинации модель × стиль DDL × стиль описания выполняется **стратифицированная k-fold кросс-валидация** (по умолчанию пять фолдов, стратификация по сложности).

```text
Для каждой модели:
  Для каждой комбинации стилей DDL и описания:
    Разбить примеры на k фолдов с сохранением долей easy / medium / hard
      Для каждого фолда:
        1. Очистить векторное хранилище
        2. Подключиться к нужной базе SQLite и выбранной модели
        3. Загрузить DDL-схемы в выбранном стиле комментариев
        4. Обучение: загрузить пары «описание — SQL» только для обучающего фолда
        5. Тест: сгенерировать SQL для запросов тестового фолда
        6. Сохранить сгенерированный SQL и результаты успешного выполнения
```

### Дизайн кросс-валидации

- **Обучающий фолд** — в векторное хранилище попадают только примеры обучающей выборки. Тестовые примеры исключаются, чтобы избежать утечки данных.
- **Тестовый фолд** — для каждого тестового запроса модель генерирует SQL с нуля. В сумме по всем фолдам каждый пример предсказывается ровно один раз для каждой комбинации.
- **Стратификация** — в каждом фолде сохраняется примерно та же доля простых, средних и сложных запросов.

### Для каждого тестового запроса

1. Модель генерирует текст SQL.
2. SQL сохраняется независимо от того, валиден он или нет.
3. Если запрос read-only (только чтение данных), он выполняется на базе.
4. При успешном выполнении с непустым результатом таблица нормализуется и сохраняется для последующего сравнения.

### Нормализация результатов

Перед сохранением и сравнением таблицы приводятся к единому виду:

1. Столбцы сортируются по алфавиту.
2. Строки сортируются по всем столбцам (значения приводятся к строкам).
3. Индекс строк сбрасывается.

Благодаря этому при сравнении не важны порядок столбцов и порядок строк внутри таблицы.

## Метрики

Для каждой комбинации предсказанные таблицы сравниваются с эталонными, и каждому примеру присваивается **метка качества**.

### Какие примеры участвуют

В оценку попадают только те примеры, для которых заранее сохранён эталонный результат выполнения. Уровень сложности берётся из таблицы с описаниями.

### Категории меток

Метки присваиваются в порядке приоритета:

| Категория | Смысл |
|-----------|--------|
| **Результат не получен** | Нет сохранённой таблицы: SQL не сгенерирован, не прошёл проверку, не выполнился или вернул пустой результат |
| **Не совпадает число строк и столбцов** | И число строк, и число столбцов отличаются от эталона |
| **Не совпадает число строк** | Отличается только число строк |
| **Не совпадает число столбцов** | Отличается только число столбцов |
| **Не совпадают значения** | Размерность совпадает, но нельзя попарно сопоставить все столбцы |
| **Полное совпадение** | Размерность совпадает, и каждый столбец предсказания полностью совпадает с отдельным эталонным столбцом |

### Сравнение значений

Когда число строк и столбцов совпадает:

1. Все значения ячеек приводятся к строкам.
2. Для каждого столбца предсказания ищется неиспользованный эталонный столбец с полным построчным совпадением.
3. Если сопоставление найдено для всех столбцов — **полное совпадение**; иначе — **не совпадают значения**.

Имена столбцов и их порядок не учитываются. Порядок строк важен: значения сравниваются по одному и тому же индексу строки.

### Как интерпретировать результаты

- **Доля полных совпадений** — основной показатель качества генерации.
- **Разбивка по сложности** — показывает, на каких уровнях easy / medium / hard система ошибается чаще.
- **Сравнение комбинаций** — помогает выбрать лучшую модель, стиль комментариев к схеме и стиль формулировки запроса.

## Настраиваемые параметры

| Параметр | Что влияет |
|----------|------------|
| Набор моделей LLM | Какие модели сравниваются между собой |
| Стили комментариев DDL | Как схема представлена модели |
| Стили описания запроса | Как сформулирован текст запроса и какой вариант базы используется |
| Источник текста запроса | Переписанное описание в нужном стиле или альтернативная колонка (например, исходная формулировка) |
| Число фолдов k | Детализация кросс-валидации |
| Сброс хранилища перед фолдом | Чистый эксперимент без остатков предыдущих прогонов |

## Сравнение с оценкой поиска

| Аспект | Оценка поиска | Оценка генерации |
|--------|---------------|------------------|
| Задача | Найти правильный пример в выдаче | Сгенерировать SQL и получить правильную таблицу |
| Корпус в хранилище | Весь датасет | Только обучающий фолд |
| Эталон | Идентификатор правильного примера | Таблица результата выполнения |
| Метрики | MRR, MAP@k, Recall@k | Категории совпадения результатов |
| Измерения стиля | Стиль описания и варианты перефразирования | Модель × стиль DDL × стиль описания |
| Валидация | Ранжирование на полном корпусе | k-fold CV со стратификацией по сложности |

## Ограничения

- Качество оценивается по **эквивалентности результата**, а не по совпадению текста SQL. Разный SQL, возвращающий ту же таблицу, считается успехом.
- Каждый фолд каждой комбинации требует переинициализации хранилища и повторной загрузки схемы, поэтому оценка вычислительно дорогая.
- Оцениваются только примеры с заранее подготовленными эталонными скриптами и результатами выполнения.
